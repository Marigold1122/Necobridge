# 1.4.6 离屏鼠标跟踪修正

用户确认：远端开始菜单打开后穿回本机，远端固定一个项目保持高亮，左边继续移动不会改变该高亮。1.4.5的微小移动没有解决用户现场表现。

本次在停车前记录WindowFromPoint命中窗口及前台GUI线程捕获窗口。隔离窗口显示后，只有停车请求仍为当前版本、光标仍在隔离范围内，且当前命中已不同于原窗口时，才对原窗口请求TrackMouseEvent(TME_LEAVE)。由USER32判断是否生成WM_MOUSELEAVE，不用PostMessage伪造，不模拟点击、不关开始菜单、不释放其他进程的鼠标捕获、不抢焦点。

依据Windows TRACKMOUSEEVENT契约：请求TME_LEAVE时，鼠标已不在指定窗口/区域上，会立即生成离开通知。新增DepartureSmoke用新建的屏幕外窗口和另一GUI线程验证，实际收到系统WM_MOUSELEAVE。该检查不移动真实鼠标、不发点击、不处理Shell窗口。

日志记录离屏前后窗口句柄、捕获句柄、跟踪成功/错误码。不记录窗口标题、进程名、用户文字、剪贴板正文或路径。保留当前停车和本地接管代际保护。

注意：此检查只证明机制可用，不证明用户远端Windows开始菜单/XAML控件已恢复。是否为悬停或键盘焦点残留，仍需实际Shell验证。不能据编译或测试窗口通过宣称根治。
