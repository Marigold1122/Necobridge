# 1.4.7 离屏鼠标捕获交接

## 现场与研究

1.4.5、1.4.6均未解决用户远端Windows开始菜单固定磁贴高亮。桌面和普通软件未报告同一现象；不能据此认定是Windows设计行为，也不能据普通WM_MOUSELEAVE测试断言开始菜单内部PointerOver恢复。

检索Deskflow、Synergy、Barrier、PowerToys公开问题，未找到完全匹配且已确认修复的Windows开始菜单条目。Deskflow #3651讨论离屏后仍触发悬停；#9461/#9448是macOS隐藏光标仍触发悬停，不能当作Windows解法。

核对Deskflow Windows MSWindowsDesks::deskLeave 的secondary路径：隐藏指针、显示hider、SetCapture(hider)、等待后deskMouseMove。源文件blob SHA dad2c38bc63136929735275eb194633b9c1e576f（https://github.com/deskflow/deskflow/blob/master/src/lib/platform/MSWindowsDesks.cpp）。本项目参考其捕获所有权交接做法，未复制源码，也不沿用其主控端AttachThreadInput/SetForegroundWindow操作或30ms延迟。

## 本轮

- 隔离窗口已显示、当前请求有效且指针仍在停车区域时，由该窗口GUI线程调用SetCapture，校验GetCapture为自身；失败按现有错误路径明确记录。
- 捕获后再次检查请求代际，再触发零距离、非合并鼠标更新。不再叠加1.4.5的一像素移动。
- Hide/Dispose在窗口自身线程，仅当GetCapture等于自身时ReleaseCapture；不清理别的窗口捕获。远端重入、本地实体接管、暂停/失联与退出沿用现有Hide路径。
- 删除1.4.6 MouseDeparture类及其外部TrackMouseEvent处理。DepartureSmoke更新为对实际生产捕获函数的生命周期检查。
- 不增加定时清理、点击、按键、Shell名称特判、前台切换、权限提升或UIAccess绕过。
- 保持停车位置、协议、右键记账、主界面字体及Alt+V原字体恢复。

当前InputRouter仍先发起异步Show并同步移动到停车点；不是照搬Deskflow全套时序。改动是隔离窗口准备完成后的显式捕获交接，不能宣传已实现原子切换。

## 验证和待验收

DepartureSmoke：实际自有窗口捕获成功、释放成功、不释放另一个自有窗口捕获、前台窗口未变。测试不操作开始菜单、不移动光标、不注入点击或键盘、不启动钩子。InputSmoke通过；Release编译通过，安装包/便携包生成，ZIP CRC与更新包哈希检查通过。

真实Windows开始菜单结果未验证，不宣称根治。两端退出旧版使用1.4.7，远端打开开始菜单并悬停磁贴后穿回本机：检查高亮是否消失且菜单仍打开；再穿回远端确认首次移动/点击可用，确认实体接管、快速往返与右键轮盘仍正常。若系统菜单因捕获变化自动关闭，也算不满足验收，不能算修好。
