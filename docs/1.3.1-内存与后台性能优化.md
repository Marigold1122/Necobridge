# NekoBridge 1.3.1 内存与后台性能优化

## 修改范围

本轮保持界面外观、历史保留规则、位移映射和配对协议不变。不使用强制GC、工作集裁剪、定时清缓存来降低任务管理器数字。

### 输入与后台

- 高频连接存活检查改为锁内直接查询，不再构造包含所有设备名称、地址和状态的UI快照。
- 正在转发键鼠时保留8ms发送合并节奏；操作本机、接收远端或空闲时定时器改为100ms。鼠标捕获与接收仍由事件即时处理，不等待100ms；400ms心跳和2秒失联释放保留。
- 主窗口隐藏时不再每秒刷新不可见的连接引导文字、动画和控件属性；重新打开时刷新状态。
- 屏幕排列页不可见时不重建通道图形，进入页面时再绘制。

### 剪贴板历史

- 不再提前解码一整页历史图片。只有已实现化的可见缩略图才加载，最多两项并行；离屏/回收时取消旧请求并释放Image.Source，防止旧图片写入已复用的条目。
- 缩略图从历史文件直接解码，不先分配完整PNG字节数组。只预览最多320×192范围，按比例缩小，不把窄长图片解码成很高的位图。数据库/原图/离线副本不变，复制时仍使用原始图片。
- 面板隐藏后释放显示列表及图片引用，并使未完成的分页失效；下次打开重新读第一页，不删除历史。保留滚动自动分页、搜索及收藏。

### 网络帧

- 不超过64KiB的接收缓冲区复用ArrayPool，解析完成或失败时清除所使用字节再归还；剪贴板数据或认证证明不会原样留在池里。
- 偶发的大型清单仍用临时数组，不把2MiB缓冲区永久留在池中。协议格式、最大帧限制和失败传播不变。

## 测量

运行 `tools/PerformanceSmoke`，Release模式。同一独立进程、临时数据、无真实窗口/钩子/系统剪贴板/网络。时间结果是单次局部测量，不代表用户整体延迟。

|项目|优化前参考|本轮实现|
|---|---:|---:|
|5台设备、10万次连接查询的托管分配|84,000,040字节|40字节（测量计时对象）|
|同上耗时|68.3ms|1.4ms|
|4KiB测试内容、3000次帧读取的托管分配|40,584,040字节|27,288,040字节|
|同上耗时|53.6ms|52.1ms|
|512×8192测试PNG的缩略图尺寸|320×5120|12×192|
|同上解码输出像素字节数|6,553,600|9,216|

缩略图像素字节数不是进程总内存，也不包含解码器的临时内存。WPF和运行时可能继续保留已经申请的工作集，释放引用后不保证任务管理器立即下降。

实施前用户当前进程短时采样约183MiB工作集、113MiB私有内存，8秒CPU增量约15.6ms。该用户进程未停止或替换，本轮没有可比较的整进程前后测试，不宣称整体内存已降至某个数值。

## 验证与未验证

- PerformanceSmoke通过：帧读取/异常/取消后的恢复、预览边界、原图不变、文件流释放后仍可用、分页、隐藏列表释放和过期查询不回填。
- InputSmoke及二维布局定向检查通过，包含此前右键轮盘释放、输入重放、本地接管、四向边界和映射规则。
- 主程序及安装包发布编译通过，0警告0错误；包完整性及更新索引另行核验。
- 未运行完整测试集、截图或视觉测试，未升级/结束用户当前程序，未使用真实剪贴板或历史数据。
- 首次进入历史列表、快速滚动图片、反复隐藏打开、双机手感和断线恢复仍需实机验收。
