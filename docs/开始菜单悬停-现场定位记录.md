# 开始菜单残留高亮：1.4.7 后的定位记录

用户确认1.4.7仍无效。停止发布猜测性修复，不把普通窗口的WM_MOUSELEAVE或捕获单元检查当成开始菜单实测。

## 已取得的现场事实

- 本机会话1，运行NekoBridge进程34504，安装路径D:/Program Files (x86)/NekoBridge/current/NekoBridge.exe，FileVersion 1.4.7.0。
- 只读WindowFromPoint命中NekoBridge隔离窗口；GetGUIThreadInfo检查其线程，Capture等于该窗口，Focus和Active为0。因此本次场景下“新版未运行”“捕获未取得”不成立。
- 系统StartMenuExperienceHost与ShellExperienceHost进程存在，和诊断进程同会话。但自动打开开始菜单的几次尝试没有观察到可见菜单窗口。UI Automation也未找到对应可见菜单。该结果是复现受阻，不代表系统菜单或本产品修好。
- 只读GetAsyncKeyState检查Shift/Ctrl/Alt/Win及左右键均非按下，排除当时修饰键处于按下状态。没有清空或重置实体按键。
- 任务栏处于屏幕底部自动隐藏位置。不能据此断言它与原问题有关。

## 工具

新增tools/StartMenuProbe，仅保留--watch OUTPUT_DIRECTORY的被动观察入口；120秒后结束。记录开始菜单范围、物理光标位置、命中句柄、UIA键盘焦点与SelectionItem选择状态；最多保存24张菜单范围截图。截图只保留本机.tools目录，不提交、不上传。UIA未提供可靠通用IsPointerOver属性，因此不能只凭selection=false断言无悬停。

工具不注册钩子、不注入键鼠、不改变捕获/焦点、不改用户数据。最初自动复现尝试均在没有找到菜单时失败，没有执行磁贴点击；自动注入路径已从工具中清理。生产代码未修改，也没有产生新版本或新Release。

下一步必须获得真实菜单打开后、穿屏前后的观察，而非继续推断。若本机不能重现，需在实际出现问题的电脑运行同一个观察工具。最终根因和修复尚未确认。
